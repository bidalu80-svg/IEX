## 上一版的问题

`build-thinking-cube-atlas.py` 原来只读取 `original[:35]`，在原始 F34 后用
0.1 秒光流补帧接回 F6。Swift 的循环长度是 `62 / 60 = 1.0333s`。
这会每秒将整个魔方姿态拉回早期方向。首尾掩码差为零只能说明人工接点相同，
不能证明速度、层动作或整体朝向与参考一致。

`TypingIndicator` 原来在第一个画面就显示完整文案，只有周期扫光，没有上升淡入。
旧提取器在 `struct TypingIndicator` 前停止，验证程序自己放了一个普通 `Text`，
所以此前的渲染验证遗漏了真实文案。

## 修正后的运动与时间

图集完整保留 F0–F55 的 56 个观察样本和对应透明度哈希。离线先消去整个图形的
平面旋转与尺度变化，保留局部转层；运行时再根据持续的绝对时间恢复整体姿态。
局部图集循环时，整体角度继续前进，文字入场时钟也继续前进。

从停稳帧 F8/17/26/35/43/52 的仿射配准估计，整个图形的平面角速度约
0.91934°/原视频帧，即 27.58°/秒。这个值是短片拟合值，后续持续转动属于外推。

文案使用延迟 `14 / 30s`、时长 `0.2s` 的二次 ease-out：
`progress = 1 - (1 - u)^2`。初始位移拟合为 9 源像素，在 56px 图标显示为
24pt 时折算为 3.857pt。对 F15–F20 的位置 RMSE 为 0.106 源像素，
透明度 RMSE 为 0.0164。保留中文文案，按参考复现整行入场。

资源共 124 个 56×56 透明帧，60Hz 采样；16 帧首次入场、108 帧局部动作循环。
图集与解码帧合计 3,161,088 字节，共享缓存预算 4MiB，响应内存警告清理。
图标和文案共用一个起始时间，普通视图更新不重设它；减少动态效果时立即显示
完整静态魔方与可读文案，后台停止动画调度。

原视频在 F55 后没有后续魔方样本，因此最后一次转层的完成过程需要重构。
这段在 atlas 索引 111–123，约 0.217 秒，并明确记录在 manifest 的
`reconstructedTail` 中。后续等待时间复用局部转层，整体旋转持续推进；
不能将参考没有展示的后续动作称作逐帧原样复现。

## 验证方式与交付边界

- `python scripts/verify-thinking-cube-atlas.py --source <原视频路径>`：核对原视频
  SHA、90 总帧、56 个等待样本、图集采样与独立双线性恢复误差；同时检查多次
  局部循环时整体角度持续前进。
- `scripts/test-thinking-glyph-ui.sh`：从生产源原样提取完整 `TypingIndicator`、
  `TypingIndicatorFrame`、调色板和采样器，在 iOS 模拟器实际渲染完整中文行，
  导出 0–0.9 秒两主题的每个 60Hz 入场帧、长等待帧与减少动态效果帧。
- 实际编译、模拟器渲染与 IPA 打包结论以对应提交的 GitHub Actions 结果为准。
  60Hz 调度和确定性帧导出不等于实机持续 60fps 测量。

独立像素恢复检查的全图平均 alpha 误差为 0.703/255，最大单帧平均误差为
1.011/255；这些值包含原视频白底提取、旋转归一化和重采样的误差，
不代表文字和整个界面的像素一致率。
