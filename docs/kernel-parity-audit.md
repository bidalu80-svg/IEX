# Kernel parity audit

Reference app: `OpenMinis/OpenMinis@1a71df0f381cefde80bf912b723de6f9831bc177`.
Its `.gitmodules` identifies `deps/ish` as `OpenMinis/ish-arm64`; the app tree pins commit `0fd17a135e78b7a0cf08a4f5831217bbb76ed22f`. This audit compares that exact dependency with `Vendor/ZeNative/ish`, rather than counting files or treating the upstream branch tip as the shipped dependency. Blob hashes and fetched wrapper hashes are in `kernel-parity-source-manifest.json`.

## Scope and result

This change repairs independently identified command cancellation, ownership, routing and path handling defects. It is **not a claim that every native kernel difference has been merged or that device runtime parity is complete**. Only targeted native offload/task metadata and bind-open flag changes were made; no whole translator/core replacement was made: Ze's existing AOJIT switch, memory pressure monitor, exit-progress safeguards and guest architecture are retained.

| Area | Source evidence | Finding and disposition |
| --- | --- | --- |
| Concurrent shell execution | `Agent/ISH/ISHExecutionCoordinator.swift`, `iSH/ISHShellExecutor.m` | Already spawns an independent `/bin/sh`, pipes and fs_context per command. No serialization added. |
| Stop responsiveness | `stopAllNonisolated`, `runCommand` | Previous main/caller thread synchronously scanned the process table under pids_lock. Now snapshots ownership and dispatches kills to a serial utility path; timeout result and 3-second stop abandonment run independently of that queue. A blocked kill no longer blocks the UI or timeout result. |
| Stop owner isolation | `InflightExec.ownerId`, `AIChatViewModel+ISHCommand.runRaw`, `AIChatViewModel+BackgroundTask.stopCurrentCommand` | Previously the chat stop called unfiltered global stop. Commands now carry the issuing chat; child Stop filters both workspace and owner. On-demand shell installation carries the same owner. Global emergency stop remains available explicitly. |
| Stuck native I/O | `registerAbandon`, `stopAbandonGrace` | Stop releases the awaiting tool result after 3 seconds if the guest never exits. This releases the wait; it does not assert that an uninterruptible native syscall has terminated. Native executor cleanup is queued separately. |
| Timeout output | `recordPartial`, `partialSnapshot` | Preserves newest output before timeout/abandon, marks truncation, bounds the mirror to 256,000 characters including an oversized individual line. |
| Continuation races | `claimResume`, late abandon registration cleanup | Existing NSLock one-shot continuation guard retained. Completion racing registration no longer leaves an already-finished abandon handle. |
| Cancel before execution | `execute` defer ordering | Removal is registered before `Task.checkCancellation`, avoiding a leaked PID-zero inflight record. This does not add arbitrary Task.cancel propagation into a running guest. |
| Filesystem routing | `Agent/ISH/ZeFsRouter.swift` | Existing forward/reverse routing and prefix boundary were functionally equivalent. Tokens now key `(workspace, owner)`: file access retains shared workspace, native browser/offload caller identity resolves the actual child. Reverse lookup uses a known-workspace set. Unknown nonzero tokens return nil; only zero legacy tokens may use mounted-session fallback. |
| Guest-thread native context | `NativeOffloads/NativeOffloadUtils.h/.m` | Adds `noff_current_fs_context` from thread-local current task before any MainActor hop; browser agent uses the coordinator caller API. |
| Native path idempotence | `noff_resolve_host_path` | Already-translated host argv paths are no longer nested under rootfs again. Sandbox/shared-container matches use a path-component boundary, including `/private/var` form. |
| Process sweep | `ISHTaskIsDescendantOf`, `killProcessGroup` | Parent chain validates task identity through pid table; root and swept tasks guard absent groups before dereference. Existing delayed root PID reuse check retained. This is upstream-equivalent hardening, not proof of complete task lifetime safety. |
| Offload command scope | `kernel/native_offload_policy.c/.h`, `kernel/exec.c` | Policy files have identical normalized Git blobs at the pinned commit; shebang bypass, explicit guest path scope and `NO_OFFLOAD` switches already exist. Existing real C tests are reused. |
| Procfs/exit memory lifetime | `kernel/exit.c`, `fs/proc/pid.c` | Ze already clears mm/mem under general_lock before release. `fs/proc/pid.c` blob is identical. Ze also has exit-progress/poll-floor changes absent in the pin; preserved. |
| AOJIT/AOT | `Agent/ISH/AOJITAcceleration.swift`, `asbestos/guest-arm64/jit.h/.c`, native preparation scripts | Ze runtime enable/disable declarations differ intentionally from the pin; no blanket replacement. Execute still starts MemoryPressureMonitor independently of AOJIT enabled state. Simulator native build remains distinct from device build. |

## Detailed disposition of remaining source differences

The comparison is by behavior and call sites, not by file counts. Scope was closed for integration after the targeted changes listed below; outstanding defects are explicitly distinguished from preserved differences.

| Component / difference | Assessment | Disposition |
| --- | --- | --- |
| `task_create_` returns NULL while holding pids_lock | Confirmed defect: any allocation failure permanently blocks subsequent forks and signal delivery. | Fixed: release lock and clear claimed PID slot. Fault injection exercises the production allocation-failure block. |
| `task_run_tlb_cleanup` deferred mm release | Confirmed defect: deferred release could destroy mm while procfs still acquires it through published task pointers. Existing do_exit already had the correct handoff. | Fixed: unpublish mm/mem under general_lock, then release outside the lock. Test asserts ordering and absence of held lock at release. |
| `fakefs_{unlink,rmdir,rename,mkdir,stat}` external bind operations | Confirmed defect: blocking host File Provider calls executed under the global metadata transaction, stalling unrelated guest filesystem work. Hook-routed workspace calls already bypassed metadata. | Fixed: external host operation precedes the metadata transaction; stat releases its read transaction before host stat. Realfs/internal transaction ordering retained. Tests inject host success/failure and assert no lock is held. |
| Hook-routed `fakefs_stat` identity | Confirmed defect: path stat left dev/nlink/blksize unset while fstat obtained host values; utilities comparing stat/fstat could report replacement. | Fixed by copying dev through dev_fake_from_real, plus nlink and blksize. Platform stat behavior still needs app/native integration validation. |
| `fakefs_readdir` and `realfs_getpath` logs | Confirmed hot-path cost: each relevant directory entry/path emitted stderr logging even in release builds. | Fixed: gate on existing DEBUG_verbose build setting. Debug builds opting into that channel retain detailed tracing. This gates costly output; it does not claim measured frame-rate improvement. |
| `realfs` flags | Host open already honored O_NOFOLLOW; bind fast path did not, and reverse flag mapping omitted it. | Both missing directions fixed. Real temporary symlink test passes for bind flags. |
| `realfs` flock proxy cleanup | Ze intentionally does not delete proxy inodes merely because their mtime is old; flock does not update mtime. | Preserve Ze behavior: unlinking a still-locked proxy permits a second exclusive lock on a new inode. Upstream diff here is mainly comments, not a missing required feature. |
| `path.c` overflow checks | Ze already has base-length, separator reservation and n<=0 checks matching the pinned upstream fix. | Functionally equivalent; preserve. |
| `path.c` cache | Ze has 64 entries per thread (~525 KB of TLS); upstream uses one 512-entry table, generation invalidation on namespace mutation and 100 ms TTL. | Actual optimization/invalidation gap. Do not transplant only the table: mutation call sites and fs_context-aware cache identity must be validated together to avoid cross-session stale symlink results. No shared-cache change in this patch. |
| `fakefs_open` read transaction/stat caching and inode lifetime | Upstream defers writer-lock acquisition for existing files, caches first fstat metadata and takes inode references earlier; Ze uses an immediate write transaction. | Actual metadata-contention optimization gap, coupled to fd/inode definitions and unlink orphan semantics. Not equivalent and not claimed fixed. |
| `fakefs_rename` orphan metadata cleanup | Upstream introduces inode_note_orphan/inode_clear_orphan lifecycle alongside open/close changes. | Related lifecycle gap requiring a coherent inode regression; not safe to copy one call without its supporting machinery. |
| `task_start` pthread_create return handling | Ze tests `< 0`, but pthread_create returns positive errno on failure. Upstream changes to an errno-returning API. | Confirmed remaining defect under thread exhaustion. Needs all launch callers and successful-copy_task resource rollback, including shared thread groups; upstream fork error path simply task_destroy does not itself release copied mm/files/fs/sighand. Scope closed before this cross-caller lifecycle change. |
| `fork.c` guard hook | Ze contains the hook, but current ISHKernel does not install the upstream footprint/fork-rate guard. Ze live mmap memory brake is present, which is not equivalent to guarding host thread/fork overhead. | Preserve working memory brake and AOJIT; fork-rate/thermal admission remains a real capability gap. Do not replace Ze atomic function pointer initialization with upstream `= NULL` (known clang compatibility fix). |
| `task.c`/`exit.c` progress guards | Ze has exit_started tracking, poll-floor timing, and orphaned-thread guards absent from the pin. | Preserve: replacing the files wholesale would remove Ze's safeguards. |
| `ISHKernel` background throttle actuator | Ze already has eager debt payment, deep-red clamp, 100 ms interruptible slices, post-sleep timestamp, cold-start debt, trylock poke and wall-time window logic. | Equivalent mechanisms; preserve Ze's intentionally lower soft/hard thresholds 24/30 s versus upstream 30/38 s. Thresholds are not validation of runtime CPU budget. |
| `ISHKernel` CPU sensor | Upstream adds TASK_THREAD_TIMES_INFO live-thread time to MACH_TASK_BASIC_INFO terminated-thread time; Ze currently reads only the latter. | Fixed: sums both sources with 64-bit nanosecond conversion and skips failed samples. Actual extracted sensor compiled/executed with injected live/dead counters; live-thread, exit handoff, fractional units, long-session overflow and both failure paths pass. Device background test remains separate. |
| `ISHKernel` crash guards and diagnostics | Upstream adds signal chaining, guarded alternate stack, JIT recovery range checks and optional CPU-top/watch diagnostics. | Diagnostic instrumentation is not a missing execution feature; crash recovery/stack checks require the exact generated CPU offsets and signal ownership. No blind offset or handler replacement. |
| Rootfs recovery | Separate focused implementation preserves broken original trees and stages/validates replacement before activation. | See `rootfs-recovery-audit.md` and its actual CI results; not counted as a coordinator test. |

Native in-process abort registration and terminating-signal forwarding are implemented in `kernel/native_offload.c/.h`, with atomic per-task publication/reset. Unlike the pinned callback taking only a signal, the Ze callback receives its target task, so cancelling a queued ffmpeg never cancels the current ffmpeg. Cancellation exit status retains the terminating signal. `FFmpegOffload.m` uses cancellable mutex acquisition and a cooperative framework interrupt hook from `0002-cooperative-interrupt.patch`; worker join precedes releasing argv, descriptors and global state. The pinned implementation copies argv after abandoning a worker, an ownership race deliberately not copied. An uninterruptible hardware driver may retain its worker until it returns; coordinator Stop bounds the visible wait without claiming to force-kill that thread.

No Windows/host policy fixture establishes Darwin guest execution, background suspension behavior or AOJIT speed. Device-specific behavior remains pending even when the macOS fixture and app build pass.

## Reproducible verification

1. `python3 scripts/test-kernel-runtime.py`: extracts the real coordinator execute/runCommand/stop machinery and complete router into a macOS Swift harness. Native execution is a deterministic boundary fixture. Verifies owner tokens/shared paths, unknown token refusal, blocked kill queue timeout, newest bounded output, owner-only stop, 3-second abandonment, sibling completion, synchronous completion and pre-cancelled cleanup. Source hashes accompany the generated harness under `$RUNNER_TEMP/ze-kernel-tests`.
2. `python3 scripts/test-native-cancellation.py`: compiles the production native signal forwarding/abort registration, FFmpeg task callback, and actual bind-open flag mapping. Tests terminating versus routine signals, owner isolation, proxy forwarding and real symlink refusal. This is a host policy test, not a full codec test.
3. `python3 scripts/test-kernel-cpu-sensor.py`: compiles the actual Mach CPU sensor with injected counter snapshots; five groups verify live-worker accounting, exit handoff, units, 64-bit totals and failed-read skip behavior.
4. `python3 scripts/test-kernel-locks.py`: compiles actual fakefs mutation functions and task failure/cleanup sections with deterministic host failure injection; verifies external I/O runs without the metadata lock, failure never starts a transaction, internal operations keep their transaction, OOM releases pids_lock and deferred mm unpublishes before release.
5. `bash Vendor/ZeNative/ish/kernel/offload_tests/path_scope/run.sh`: compiles and runs existing native path-scope policy C cases with warnings as errors.
6. Full existing workflow device + simulator build: typechecks actual Swift/Objective-C bridging and links native libraries. The coordinator harness does not replace this check.
7. Device guest scenarios still to execute: concurrent parent plus two children in shared workspace; stop one child while sibling writes its own live output; timeout after output; stop blocked file-provider I/O; foreground/background transition under CPU load; AOJIT enabled/disabled comparison. Existing `scripts/ish-regress/regress_proc_exit_race.sh` is a guest script, not a host-only test.

At authoring, both Python harnesses completed `--prepare-only` and scoped `git diff --check` passed on Windows. Both FFmpeg patches applied together successfully to official FFmpeg n6.1.2 (`0002` second hunk offset 17 lines due to existing reset patch), and both hook definitions were verified in the patched result. The coordinator fixture subsequently passed all 17 cases in the macOS integration run (root tracks the exact SHA/run). Native cancellation and kernel-lock C fixtures were actually compiled and executed on WSL Ubuntu with clang 16, exit 0; these are host-boundary tests, not guest or iOS hardware verification. The full final device/simulator build must still be reported against its exact final SHA/run.

## Rollback

Review the targeted source diff and revert the owning integration commit if runtime verification fails. No live rootfs, user workspace or installed application data was modified by this audit. Reference files and diff caches were kept under the system temporary directory; only audited source changes, this document, the manifest and test harness are repository deliverables.
